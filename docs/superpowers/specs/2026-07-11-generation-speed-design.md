# 条漫生成效率优化设计文档

## 背景

当前条漫生成总耗时约 50s，其中图片生成占 56%（~30s），是最大瓶颈。需要优化生成效率，降低总耗时。

## 目标

总耗时从 ~50s 降到 ~40s，图片生成时间从 ~30s 降到 ~20s。

## 方案

### 1. 异步重试改造

**问题**：`generate_with_retry` 是同步方法，使用 `time.sleep` 阻塞线程池中的线程，通过 `run_in_executor` 调用。并发时线程池被阻塞，影响整体效率。

**方案**：将图片生成改为纯异步实现：
- 用 `httpx.AsyncClient` 发送 HTTP 请求
- 用 `await asyncio.sleep(wait)` 代替 `time.sleep(wait)`
- 不再使用 `run_in_executor`

**改动文件**：`app/llm/qianfan_image_provider.py`

### 2. 提高并发数

**问题**：硬编码 `Semaphore(2)`，并发数太低，图片生成需要 3 轮才能完成 6 张。

**方案**：将并发数从 2 提升到 3。

**依据**：
- 当前 2 并发时偶尔遇到 429，但重试一次就成功
- 3 并发可能遇到更多 429，但由于重试机制的存在，总时间仍然更短
- 6 张图片从 3 轮（2+2+2）变成 2 轮（3+3）

**改动文件**：`app/services/strip_service.py`

## 预期效果

| 指标 | 当前 | 优化后 |
|------|------|--------|
| 图片生成时间 | ~30s | ~20s |
| 总耗时 | ~50s | ~40s |
| 并发数 | 2 | 3 |
| 重试方式 | 同步阻塞 | 异步非阻塞 |

## 风险与应对

1. **429 限流增加**：并发提升后可能遇到更多限流
   - 应对：保持现有的指数退避重试策略，首次失败等待 3-5s

2. **请求失败率上升**：并发太高可能导致更多失败
   - 应对：如果 3 并发失败率太高，可以调回 2.5 或 2
